# Global counter: вычисление, фиксация и восстановление в CiffSelect

## Ключевой вывод

Глобальные счётчики обслуживает `CiffSelect.dll`, интерфейс `ICiffSelection` IID `38a16253-14bf-483d-9653-3a8dec06e38d`. DataFile получает этот интерфейс через `ImageMgr.dll:0x456c4f70` и хранит object+8. Чтение global counter 14 выполняется через `ICiffSelection.GlobalCounterValue.get`, slot +0x50, с аргументом 14. Реализация — `CiffSelect.dll:0x458f8df8`, контейнер счётчиков — selection object+0xc48.

`ICiffSelection.UpdateFields/UpdateFieldsEx` с флагом COUNTERS=2 выполняет и вычисление следующего значения, и перенос его в текущее/global map. Это логическая фиксация внутри обновления CIFF; сама по себе она не является доказательством физически нанесённого кода. Для привязки к реальному циклу нужно сопоставить внешние вызовы ImageMgr/LocalPrintheadProtocol.

## Проверенные slots

Vtable `0x45938fa8`, имена встроенной type library сопоставлены с ARM реализациями:

| Offset | Метод | Реализация |
|---|---|---|
| +0x18 | UpdateFields | 0x45917488; делегирует +0x1c |
| +0x1c | UpdateFieldsEx | 0x4591bfc4 |
| +0x34 | CountsRequireSaving.get | 0x458f8db0 |
| +0x38 | CountsRequireSaving.put | 0x458f7320 |
| +0x3c | RemoveOldCountFiles | 0x458f7334 → 0x4591fc6c |
| +0x40 | ResetImageData | 0x4590f738 |
| +0x44 | UpdateJobParameters | 0x458f41e0 |
| +0x48 | LoadJobParameters | 0x458f3358 |
| +0x4c | RemoveJobParameters | 0x458f3f4c |

Следовательно, slot +0x3c и +0x40 нельзя называть подтверждением commit печати: это удаление старых файлов счётчиков и сброс image data. +0x44 не обновляет счётчики: это job parameters.

## Доказанная цепочка логического increment

Прямые ARM BL:

`UpdateFieldsEx 0x4591bfc4` → call `0x4591c150` → `0x4591bbfc` → call `0x4591be90` → `0x4591b934` → call `0x4591baf8` → `0x4591b554` → call `0x4591b6e4` → `0x4591ae60`.

В `0x4591ae60` значение типа CounterText==5 проверяется в `0x4591b02c`. Бит 2 update flags проверяется в `0x4591b034`; при его наличии call `0x4591b070` вызывает `0x4591984c`. Флаги проходят с исходного r3 UpdateFieldsEx через stack без замены (`0x4591bc0c`, `0x4591be88`, `0x4591baec`, `0x4591b6bc`, `0x4591af18`). Type library называет бит 2 `IUF_COUNTERS`; это имя согласуется с исполнением.

`0x4591984c`:

1. Читает `ParentCounter` slot +0x114 (`0x459198cc`). Проверяет его соответствие текущей зависимости (`0x459198e0`…`0x45919904`); неподходящие ветви пропускаются.
2. Читает `PrintsPerCount` slot +0x104 (`0x45919920`) и `PrintsThisCount` +0x11c (`0x45919940`). Если PrintsThisCount>1, записывает значение-1 через +0x120 (`0x4591996c`) и возвращается без increment. Когда требуется increment и PrintsPerCount>1, записывает PrintsThisCount=PrintsPerCount (`0x45919990`).
3. Запускает два прохода: sl=0 (`0x45919a2c`), в конце sl++ (`0x45919db0`), повтор пока sl<2 (`0x45919dc0`…`0x45919dc4`).
4. В проходе 0 call `0x45919b34` → `0x45917508`. Функция получает Start/End/CurrentValue, StepSize, диапазон символов, выполняет арифметику (`0x459178ac` / `0x45917924`) и записывает **NextValue** через +0x88 (`0x45917950`). Обрабатывает rollover; это не простое безусловное +1 для всех видов счётчика.
5. В проходе 1 call `0x45919ba0` → `0x459181f0`. Здесь `NextValue.get +0x84` (`0x45918264`) → `CurrentValue.put +0x58` (`0x4591829c`). Если Global==1, читает GlobalID +0x98 (`0x459182c0`) и вызывает `0x45920ea0` (`0x459182f0`). ID=-1 (Line) заменяет на lineID+0x10; ID14 остаётся14.
6. `0x45920ea0` обновляет/вставляет строковое значение в global map (element size0x2c) и устанавливает dirty byte container+0x1c=1 (`0x45920ff8`). Никакого аппаратного подтверждения печати между NextValue и этой записью в показанной цепочке нет.

Глобальный map допускает 0…31 (`0x458f8e14`, `0x45920ed0`), хотя сериализованный GlobalID пользовательского subcounter ограничен -1…15. Верхняя половина зарезервирована преобразованием Line→lineID+16.

## Сохранение и восстановление

Контейнер имеет два пути сохранения:

- Компактное состояние: устройство **`RTC1:`**, строка `0x4594a19c`, конструктор `0x459254a0`. Открытие `0x459254d8`; чтение `DeviceIoControl` с кодом `0x00222004` в `0x459255ac`, запись `0x00222008` в `0x45925664`. Ограничение address+size <=0xfe. Данный драйвер здесь не разобран; его физическая долговечность при потере питания не доказана.
- XML fallback: `CurrentCounts.1.xml` и `CurrentCounts.2.xml` в заданной папке. `0x4591f1e4` формирует snapshot только если dirty byte+0x1c !=0. Если все записи помещаются в выделенный compact storage и имеют поддерживаемое представление, сохраняет compact buffer через `0x459255e4` (`0x4591f4d4`). Иначе формирует XML snapshot в одном из двух буферов и будит writer через `SetEvent` (`0x4591f7e0`). Writer-thread `0x4591ed9c` → `0x4591e0c4`; последний чередует файлы, вызывает CreateFileW/WriteFile/CloseHandle (`0x4591e180`, `0x4591e1a8`, `0x4591e1b0`). Возвращаемое значение WriteFile здесь не проверяется перед освобождением буфера; FlushFileBuffers в этом фрагменте нет.

`0x459217f4` восстанавливает значения: сначала читает compact backing (`0x45921860`); если оно непустое и распознано, декодирует. Иначе получает время обоих XML (`0x45921910`) и выбирает более новый файл (`0x45921940`…`0x4592197c`). Фактическое XML чтение/разбор — `0x459214f4`.

После `UpdateFieldsEx` вызывается snapshot `0x4591f1e4` при `0x4591c17c`, включая случаи отрицательного HRESULT от предыдущего обновления (вызов стоит до проверки результата). Следовательно, негативный результат обновления сам по себе не гарантирует откат всех счётчиков.

`RemoveOldCountFiles` `0x4591fc6c`: при наличии global map очищает 16 per-job map, сохраняет оставшееся глобальное состояние, затем удаляет оба CurrentCounts файла. При отсутствии global map очищает compact backing. Метод не удаляет существующий global map. `ResetImageData` `0x4590f738` очищает выбранный per-job map и сбрасывает transient flags; не следует считать его сбросом global counter14.

## Практическая граница

В supplied microSD отсутствуют CurrentCounts.1.xml/2.xml и дамп состояния RTC1:. Поэтому текущее runtime значение global counter14 из этого образа восстановить нельзя. CurrVal в CIFF — сохранённое значение задания, а не доказательство фактической последней печати.

Код показывает двухпроходное обновление и независимое сохранение состояния. Exactly-once нанесение, последствия механического abort, rollback и power-loss outcome требуют сопоставления с внешними print callbacks либо стенда. Отсутствие внешнего ACK внутри рассмотренной функции не доказывает, когда её вызывает весь аппаратный цикл.
