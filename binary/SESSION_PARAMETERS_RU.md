# Сеанс ZBC2 и XML параметров: продолжение 5 ноября 2026

Исследованы инструкции ARM из `ZBC2.dll` версии 409720.r12.SP5. Адреса ниже — виртуальные адреса исходного PE. Это восстановление выбранных путей, а не проверка обмена с физическим принтером.

## Начало сеанса

В worker `0x446A4B78` исходный запрос информации содержит теги `IR_STS=1` и `IR_CMV=7`. Сериализатор `0x446AE038` пишет:

| Поле | Тип |
|---|---|
| Тип IRQ | u16 LE, `0x5001` |
| Полный размер внутреннего сообщения | u32 LE |
| Число тегов | u16 LE |
| Теги | указанное число u16 LE |

Байты для `[1,7]`: `01500c000000020001000700`. Они совпали с выполнением исходного ARM-сериализатора в Unicorn. Это внутреннее сообщение: для TCP ещё нужна транспортная оболочка A5/E4.

Worker ждёт связанный по номеру сообщения ответ `0x5002`, разбирает сведения CMV, ограничивает версию сверху числом **11**, а маску возможностей — `0x000FFEDF` (`0x446A4F60–0x446A4F78`). В коде есть дополнительные ветви совместимости; простое принудительное объявление версии 11 не заменяет их.

Предложение версии `0x5020`, сериализатор `0x446ABC80`: `u16 type`, `u32 total=12`, `u16 version`, `u32 features`. Проверочный пример 11/0x000FFEDF: `20500c0000000b00dffe0f00`. Это контрольный пример раскладки, а не безусловная стартовая настройка клиента.

При версии от 4 worker в определённых ветвях TCP выполняет внутренний XML-запрос конфигурации TCPIP. Проверяет `//Col[@id='BinaryCommunications']/Str[@id='NetworkClient']`, затем запасной путь `//Col[@id='TCPIP']/Str[@id='ZBC Client']` и сравнивает со своим соединением. Соответствующая ветвь выставляет бит `0x800`. Проверка находится в `0x446A4398–0x446A45A8`.

**Кодировка зависит от согласованного состояния.** Нельзя без проверки считать все соединения Unicode. Для строк Unicode исходный сериализатор использует UTF-16LE и длину u32; для legacy — Windows CP_ACP и длину u16. Конкретная ANSI-кодовая страница этим разбором не установлена.

## XML-запрос и ответ

Внешний метод SendXML `0x446E2B9C` выбирает `0x5012`, если версия протокола меньше 3 и длина XML не больше 65535; иначе `0x5112`. Общий сериализатор — `0x446A4A48`. Соответствующие ответы: `0x5013` и `0x5113`. Unicode-варианты запроса и ответа сравнены с выполнением исходного сериализатора.

Обработчик `0x446CF5C0` извлекает строку, вызывает интерфейс дерева параметров через vtable+0x28 и при успехе формирует ответ. При HRESULT `0x80040249` выбирает причину отказа 33, в другой показанной ветви — 1. Транспортное подтверждение блока и успешное выполнение XML-транзакции — отдельные события.

Точная строка из прошивки, адрес `0x446F6640`:

```xml
<?xml version="1.0" ?>
<Params><Col id="System"><Col id="TCPIP" getFlags="10" getDepth="-1"/></Col></Params>
```

Путь FT_CURRENTPARAMETERS использует точную строку по `0x44702B20`:

```xml
<?xml version="1.0" ?><Params><Col id="" getFlags="32" getDepth="-1"/></Params>
```

В `parameter_queries.py` эти два штатных литерала отделены от предложенных узких запросов к PrintInformation, Ribbon, iAssure и Performance. По умолчанию узкий запрос использует getDepth=1, чтобы включить непосредственных детей коллекции, и широкую выборку getFlags=10. getDepth=0 выводит только сам Col. Структура узких запросов построена по восстановленной модели; ответ живого устройства для каждого пути пока не получен. Извлечение значений сохраняет исходный тип, атрибуты и число без произвольного пересчёта единиц.

## Готовые части для дальнейшей интеграции

`session_recipes.py` создаёт байты IRQ, предложения версии и XML-запроса. Он требует явно указать кодировку, не открывает соединение и допускает только селекторы чтения `Params/Col`. `parameter_queries.py` создаёт XML и разбирает типизированные значения ответа. `zbc_codec.py` обеспечивает отдельный транспортный слой.

Для рабочего драйвера ещё нужны проверенные переходы состояния сеанса, полная политика ACK/NAK, таймаутов и повторов, жизненный цикл подписок и файловых транзакций. Нельзя подменять эти части отправкой одного сохранённого пакета. Запись расширенных настроек требует отдельной проверки прав, допустимых диапазонов и результата применения. Число `flags` в сохранённом XML само по себе не устанавливает такое право.

## Проверяемость

В `evidence/session/` приложены отдельные ARM-диапазоны: начальный worker, IRQ, предложение CMV, выбор XML-типа, сериализация, обработчик ответа и проверка Unicode. Эмулятор выполняет оригинальные инструкции выбранных функций с подставленными низкоуровневыми runtime-функциями; Windows CE, реальная сеть и печатающий механизм не эмулируются.
