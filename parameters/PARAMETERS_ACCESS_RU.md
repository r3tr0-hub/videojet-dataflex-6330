# ProjectInformationManager: getFlags, getDepth и запись значений

Проверен ARM-код **ProjectInformationManager.dll**, SHA-256 `fae6c09d72d38f7885e62f8c345e8e21d54e37a15742b08c5b190208e7063a4c`. Адреса ниже — виртуальные адреса именно этого файла с ImageBase 0x44400000. Сетевой доступ к устройству не выполнялся.

Разделены три разных числа: **getFlags запроса**, **flags параметра, возвращаемые XML** и **внутренние flags живого объекта**. Сохранённое `flags="519"` не является универсальным разрешением записи. У него есть бит 512, используемый экспортом и путём изменения значений, но далее действуют проверки состояния объекта, типа, диапазона, обработчики изменений и ограничения внешнего диспетчера/сессии.

## Чтение и XML-экспорт

Рекурсивный обработчик XML `0x444254e8` читает атрибуты из узла: `id`, `flags`, `getDepth`, `getFlags`. Имена находятся в таблице `0x4445c7d8`. По умолчанию getDepth=-1; эффективный getFlags=0x40, если вызывающий код не передал другое ненулевое значение. Атрибуты getDepth/getFlags переопределяют эти значения (`0x444256d0…0x444257e4`).

В `0x44425db4` полученные depth и flags передаются экспортирующему интерфейсу объекта, vtable+0x14. Для Num этот метод — `0x4442e660` (таблица `0x444492c0`), для Col — `0x444040f0`.

| getDepth | Поведение Col, доказанное `0x44404348…0x444043e8` |
|---:|---|
| 0 | экспортируется текущий Col, дети не обходятся |
| положительное | при переходе к детям уменьшается на 1 |
| -1 | обход продолжается с -1, то есть без ограничения глубины |
| иное отрицательное | дети не обходятся |

Фактический предикат экспорта параметра — **`0x4442fe9c`**. В отличие от фильтра импорта, он получает живой объект и проверяет внутренние флаги.

| Бит getFlags | Установленная операция в предикате экспорта |
|---:|---|
| 0x0002 | включает параметр после предварительных проверок категорий/скрытости |
| 0x0020 | включает объект, если его flags содержат 0x0200 |
| 0x0040 | включает flags 0x0001 при отсутствии внутреннего 0x1000 |
| 0x0100 | разрешает прохождение предварительной проверки внутреннего 0x1000 |
| 0x0200 | включает flags 0x8000 при отсутствии внутреннего 0x1000 |
| 0x0400 | включает flags 0x20000 |
| 0x2000 | исключает объекты без flags 0x200000 |
| 0x4000 | исключает объекты с flags 0x200000 |
| 0x8000 | включает flags 0x200000 |
| 0x10000 | включает оставшиеся объекты после предварительных проверок |

Внутренний flags 0x400000 принудительно включает объект раньше этих проверок. Поэтому выражение «getFlags=10 возвращает абсолютно всё» неточно: это широкая выборка, но предварительная проверка внутреннего 0x1000 остаётся, если не задан getFlags 0x100.

**getFlags=10 = 0x0a**: бит 2 даёт широкую выборку параметров; бит 8 в предикате Col `0x44403ff8` включает Col независимо от наличия подходящих потомков. **getFlags=32 = 0x20** выбирает параметры с битом 0x200. Числа 10 и 32 не являются двумя уровнями прав пользователя.

Бит **0x4** управляет объёмом метаданных: в Num-экспорте `0x4442e82c` он пропускает атрибуты flags/numType/min/max/interval/def; аналогично Col `0x444042d8` пропускает flags. Следовательно, бит 8 не означает «показывать метаданные». Экспортируемый flags маскируется константой **0x003a8f07**, поэтому XML не отражает все внутренние биты объекта (`0x4442e844…54`).

Отдельный **фильтр импорта `0x444220bc`** принимает getFlags и flags из входного XML. При бите getFlags 2 он принимает любой ненулевой flags; при 0x20 — flags 0x200; при 0x40 — flags 1. Он также имеет отдельные проверки категорий 0x100000/0x200000. Его нельзя подменять предикатом живого объекта, хотя базовое соответствие 32→512 совпадает.

## Формат значений и запись

Таблица типов `0x4445cb10`, инициализация `0x44445e54` из `0x4445b40c`, даёт точные XML-теги:

| Тип | Тег |
|---:|---|
| 2 | Col |
| 3 | DT |
| 4 | DO |
| 5 | Evt |
| 6 | Fld |
| 7 | Num |
| 8 | Sta |
| 9 | Str |
| 10 | Lnk |

Контейнер — `Params`; дерево формируется вложенными `Col id="…"`. Существующее значение помещается в текст узла своего типа, идентификатор — в `id`. Число Num читается через DOM text, vtable+0x68, и преобразование `0x4442adb8` (`0x4442b9a8…0x4442b9dc`). Значения не передаются атрибутом `value`.

Путь изменения **существующих значений**: рекурсивный обход `0x4442b3b0`, затем Num `0x4442b87c`, Sta `0x4442bb20`, Evt `0x4442bdc4`, Str `0x4442c01c`. Для Num по полученному объекту сначала читаются его актуальные flags и проверяется:

```text
(flags & 0x120) == 0 and (flags & 0x200) == 0x200
```

Только после этого вызывается setter, vtable+0x48 (`0x4442ba3c…0x4442ba6c`). То же условие повторяется в соответствующих путях других типов. Отказ/пропуск преобразуется локально в S_FALSE, а некоторые вызывающие уровни нормализуют его до S_OK (`0x4442ba78`, `0x4442ba98`). Поэтому успешное завершение XML-запроса само по себе ещё не подтверждает изменение каждого узла.

Внутренний числовой setter `0x4442e4e4` дополнительно:

- возвращает 0x80040234 при внутреннем flags 0x20;
- меняет current только при min ≤ newValue ≤ max;
- **при выходе за диапазон оставляет прежнее current и возвращает S_OK**;
- после действительного изменения вызывает механизм уведомлений `0x4442fb64`.

Эта особенность проверена исполнением настоящих ARM-инструкций на синтетическом объекте с min=10, max=20, current=12:

| flags объекта | Запрошено | Сохранено | HRESULT |
|---:|---:|---:|---|
| 519 | 9 | 12 | S_OK |
| 519 | 15 | 15 | S_OK |
| 519 | 21 | 12 | S_OK |
| 551 = 519+0x20 | 15 | 12 | 0x80040234 |

Условие допустимости XML-записи для flags 519 выполняется, поскольку 519=0x207. Это подтверждает только прохождение указанной внутренней проверки. Оно не доказывает доступность любой настройки по сети или отсутствие ограничений конкретной сессии. Полный XML-импорт определений с атрибутами flags/min/max отличается от изменения существующего значения; смешивать эти операции в SCADA не следует.

Практический результат для интеграции: читать тип и диапазон, передавать значение в корректном узле, учитывать результат отдельного узла, затем повторно читать фактическое значение. ACK/S_OK не заменяет readback.

## Воспроизведение и полнота

`verify_parameter_primitives.py` исполняет в Unicorn реальный код:

- фильтр импорта 0x444220bc;
- предикат экспорта 0x4442fe9c;
- точный блок допуска XML-записи 0x4442ba3c…0x4442ba58;
- числовой setter 0x4442e4e4, с заменой только critical-section и уведомляющего вызова.

Путь DLL задаётся аргументом либо `VJ_BIN_ROOT`; SHA-256 проверяется до эмуляции. Результаты сохранены в `parameter_primitives_test.json`, адресный листинг — `ProjectInformationManager.dll.asm`. Эти тесты не исполняют полный COM/MSXML-диспетчер, удалённую сессию или аппаратные обработчики. Значения public flags не снабжены предположительными именами вроде «admin writable»: приведены только доказанные проверки битов и наблюдаемое поведение.
