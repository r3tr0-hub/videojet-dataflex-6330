# Read and write Params

For a first connection, use the read-only recipe from the Windows client:
`<Params><Col id="" getFlags="10" getDepth="-1"/></Params>`.
This is a wide query, not an access grant. A narrower print-head read is generated by
`python3 binary/parameter_queries.py --recipe print_settings`.

The response uses nested `Col id="…"` and typed leaves (for example `Num`, `Sta`, `Str`). Keep the raw value and attributes. Look up units and scaling for that leaf, and do not assume that every numeric leaf uses the same multiplier.

For implementation of a write, preserve the tree path and type. The existing-value handler reads the value from **element text**, not a `value` attribute. Conceptual shape only:

```xml
<Params>
  <Col id="COLLECTION_FROM_READBACK">
    <Num id="LEAF_FROM_READBACK">15</Num>
  </Col>
</Params>
```

There are multiple import/dispatch paths. Do not treat that fragment as a verified, ready-to-send network recipe. See [ARM evidence and conditions](PARAMETERS_ACCESS_RU.md). The recovered existing-value path checks `(flags & 0x120) == 0` and `(flags & 0x200) != 0` against the **live object**. Exported flags are masked. A numeric setter can return S_OK while leaving an out-of-range value unchanged.

Implement one explicit write at a time: read the live type, limits and value; encode using the observed raw scale; send through the correct session handler; inspect the application result; read the actual value again. On timeout, read back before retrying. Do not import a whole snapshot as a way to change one setting.
